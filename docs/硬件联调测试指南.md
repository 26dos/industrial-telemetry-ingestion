## 1. 系统架构

联调测试的整体拓扑：

```
┌──────────────────┐       RS485 双绞线        ┌──────────────────────────┐
│  PC (Ubuntu)     │◄═══════════════════════►│  RK2612A (Ubuntu 20.04)  │
│                  │   A──A   B──B            │                          │
│  USB-to-RS485    │                          │  RS485-0 (PIN 5/6)      │
│  转换器          │                          │                          │
│                  │                          │  ┌────────────────────┐  │
│  运行:           │                          │  │ Mosquitto Broker   │  │
│  modbus_simulator│                          │  │ :1883 / :8083(WS)  │  │
│  (Modbus Slave)  │                          │  └────────┬───────────┘  │
│                  │                          │           │              │
│                  │       以太网              │  ┌────────┴───────────┐  │
│                  │◄─────────────────────────│  │ Node.js 后端 :3000 │  │
│                  │                          │  │ ├─ mqttService     │  │
│  浏览器访问:     │                          │  │ └─ modbusService   │  │
│  http://RK_IP:3000                          │  │    (RS485轮询)     │  │
│                  │                          │  └────────────────────┘  │
└──────────────────┘                          └──────────────────────────┘
```

**数据流**：

1. **采集链路**：Modbus 模拟器(PC) → RS485 → modbusService(RK) → MQTT → 前端
2. **遥调链路**：前端 → HTTP → 后端 → MQTT → modbusService → RS485 → 模拟器(PC)

## 2. 硬件准备

### 2.1 所需物料

| 物料 | 说明 |
|------|------|
| RK2612A 主板 | 采集控制单元，已烧录 Ubuntu 20.04 系统 |
| 12V DC 电源 | 9~36V 均可，推荐 12V，接线端子 KF2EDGK-5.08-3P |
| 网线 | 连接 RK2612A 和局域网（路由器/交换机） |
| USB-to-RS485 转换器 | PC 端使用，推荐 CH340/FT232 芯片，Ubuntu 免驱 |
| 双绞线 | 连接 RS485 A/B 信号线，建议使用屏蔽双绞线 |
| PC（Ubuntu） | 运行 Modbus 模拟器 |

### 2.2 RK2612A 通电与 SSH

1. **接线**：将 12V 电源接到 3PIN 电源端子（PIN1=DC+, PIN2=DC-, PIN3=PE 地）
2. **网线**：用网线将 RK2612A 的任一网口连接到局域网
3. **查找 IP**：

```bash
# 方法1：在路由器管理页面查看新接入设备的 IP
# 方法2：在同一局域网的 PC 上扫描
sudo apt install -y nmap
nmap -sn 192.168.31.0/24    # 根据你的网段调整
```

4. **SSH 登录**：

```bash
ssh root@<RK2612A的IP>
# 默认用户名/密码请查阅 RK2612A 出厂文档
# 常见默认: root / root 或 root / cosofteck
```

5. **确认系统信息**：

```bash
uname -a           # 应显示 armv7l 或 aarch64
cat /etc/os-release # 应显示 Ubuntu 20.04
df -h               # 确认 8GB eMMC 空间
free -m             # 确认 512MB 内存
```

## 3. RS485 接线

### 3.1 RK2612A 端口定义

RK2612A 通过 16PIN 3.5mm 凤凰端子提供 6 路 RS485：

| PIN | 信号 | 设备名 |
|-----|------|--------|
| 5 | RS485_A0 | /dev/ttyS0（需确认） |
| 6 | RS485_B0 | |
| 7 | RS485_A1 | /dev/ttyS1 |
| 8 | RS485_B1 | |
| 9 | RS485_A2 | /dev/ttyS2 |
| 10 | RS485_B2 | |
| 11 | RS485_A3 | /dev/ttyS3 |
| 12 | RS485_B3 | |
| 13 | RS485_A4 | /dev/ttyS4 |
| 14 | RS485_B4 | |
| 15 | RS485_A5 | /dev/ttyS5 |
| 16 | RS485_B5 | |

### 3.2 接线方法

```
  PC 端 (USB-RS485)              RK2612A 端
  ┌─────────────┐                ┌─────────────┐
  │  A (Data+)  │───── 双绞线 ───│  A0 (PIN 5) │
  │  B (Data-)  │───── 双绞线 ───│  B0 (PIN 6) │
  │  GND        │───── 可选 ─────│  GND        │
  └─────────────┘                └─────────────┘
```

**注意事项**：
- A 对 A，B 对 B，不要交叉
- 如果距离较远（>10米），建议连接 GND 参考地
- 如果只有一台设备在总线上，将 RK2612A 上对应的拨码开关（Switch 1-8）拨到 ON，启用 120Ω 终端电阻

### 3.3 确认串口设备名

SSH 登录 RK2612A 后，确认 RS485 对应的设备文件：

```bash
# 查看所有串口设备
ls -la /dev/ttyS*
ls -la /dev/ttymxc*   # 某些 ARM 平台使用 ttymxc
ls -la /dev/ttyAMA*   # 某些平台使用 ttyAMA

# 查看内核串口识别信息
dmesg | grep -i tty
dmesg | grep -i serial
dmesg | grep -i 485

# 查看设备树中的串口
ls /sys/class/tty/ | grep -v "tty[0-9]"
```

记下实际的设备名（如 `/dev/ttyS3`），后面配置要用。

## 4. PC 端准备（Modbus 模拟器）

PC 作为 Modbus Slave（模拟逆变器），RK2612A 作为 Modbus Master（采集端）。

### 4.1 安装 USB-to-RS485 驱动

Ubuntu 下大部分 USB-RS485 转换器免驱：

```bash
# 插入 USB-RS485 转换器后查看设备
dmesg | tail -20
ls /dev/ttyUSB*
# 通常会出现 /dev/ttyUSB0
```

如果没有出现，安装 CH340 驱动：

```bash
sudo apt install -y linux-modules-extra-$(uname -r)
sudo modprobe ch341
```

### 4.2 安装 Python 依赖

```bash
sudo apt update
sudo apt install -y python3 python3-pip
pip3 install pymodbus==3.6.9 pyserial
```

> 如果 pip3 报 "externally-managed-environment" 错误（Ubuntu 23.04+），使用：
> ```bash
> pip3 install --break-system-packages pymodbus==3.6.9 pyserial
> ```
> 或使用 venv：
> ```bash
> python3 -m venv ~/modbus-env
> source ~/modbus-env/bin/activate
> pip install pymodbus==3.6.9 pyserial
> ```

### 4.3 传输模拟器脚本

将项目中的模拟器脚本传到 PC：

```bash
# 从开发机 scp 到 PC（如果 PC 就是开发机则跳过）
scp tools/modbus_simulator.py user@PC_IP:~/
```

### 4.4 启动模拟器

```bash
# 基本用法：模拟锦浪逆变器，地址1，波特率9600
python3 modbus_simulator.py --port /dev/ttyUSB0 --address 1 --baud 9600 --model ginlong

# 模拟华为逆变器
python3 modbus_simulator.py --port /dev/ttyUSB0 --address 1 --baud 9600 --model huawei

# 禁用动态数据更新（寄存器值固定不变）
python3 modbus_simulator.py --port /dev/ttyUSB0 --address 1 --baud 9600 --dynamic 0

# 每 3 秒更新一次数据
python3 modbus_simulator.py --port /dev/ttyUSB0 --address 1 --baud 9600 --dynamic 3
```

启动后会看到：

```
INFO:ModbusSimulator:============================================================
INFO:ModbusSimulator:Modbus RTU Slave 模拟器
INFO:ModbusSimulator:  串口:     /dev/ttyUSB0
INFO:ModbusSimulator:  从站地址: 1
INFO:ModbusSimulator:  波特率:   9600
INFO:ModbusSimulator:  逆变器:   ginlong
INFO:ModbusSimulator:  动态更新: 每5秒
INFO:ModbusSimulator:============================================================
INFO:ModbusSimulator:模拟器启动中... (Ctrl+C 停止)
```

### 4.5 手动验证模拟器（可选）

在 PC 上用 `mbpoll` 验证模拟器是否正常响应：

```bash
# 安装 mbpoll
sudo apt install -y mbpoll

# 另开一个终端，读取寄存器 3001-3010（需要第二个串口或用 TCP 测试）
# 注意：同一串口不能同时被两个程序占用
# 如果 PC 有第二个 USB-RS485 转换器：
mbpoll -m rtu -a 1 -b 9600 -t 3 -r 3001 -c 10 /dev/ttyUSB1
```

## 5. RK2612A 端部署

### 5.1 安装 Node.js 18 (ARM)

```bash
# 检查 CPU 架构
uname -m
# 如果是 armv7l:
wget https://nodejs.org/dist/v18.20.8/node-v18.20.8-linux-armv7l.tar.xz
# 如果是 aarch64:
wget https://nodejs.org/dist/v18.20.8/node-v18.20.8-linux-arm64.tar.xz

# 解压安装
tar -xf node-v18.20.8-linux-*.tar.xz
cp -r node-v18.20.8-linux-*/bin/* /usr/local/bin/
cp -r node-v18.20.8-linux-*/lib/* /usr/local/lib/
cp -r node-v18.20.8-linux-*/include/* /usr/local/include/
cp -r node-v18.20.8-linux-*/share/* /usr/local/share/

# 验证
node -v   # 应显示 v18.20.8
npm -v    # 应显示 10.x
```

> **注意**：如果网络环境下载慢，可在开发机下载后 scp 传输：
> ```bash
> # 开发机
> scp node-v18.20.8-linux-armv7l.tar.xz root@RK_IP:~/
> ```

### 5.2 安装编译工具链

`modbus-serial` 依赖 `serialport`（C++ 原生模块），需要编译工具：

```bash
sudo apt update
sudo apt install -y build-essential python3 make gcc g++
```

### 5.3 安装 Mosquitto

```bash
sudo apt install -y mosquitto mosquitto-clients
```

配置 WebSocket 支持（前端 MQTT 需要）：

```bash
cat > /etc/mosquitto/mosquitto.conf << 'EOF'
pid_file /run/mosquitto/mosquitto.pid
persistence true
persistence_location /var/lib/mosquitto/

listener 1883
protocol mqtt

listener 8083
protocol websockets

allow_anonymous true

log_dest file /var/log/mosquitto/mosquitto.log
include_dir /etc/mosquitto/conf.d
EOF

# 重启 Mosquitto
systemctl restart mosquitto

# 验证端口
ss -tlnp | grep mosquitto
# 应看到 1883 和 8083 两个端口
```

### 5.4 传输项目

从开发机将项目传到 RK2612A：

```bash
# 开发机上执行（排除 node_modules 和 dist）
cd /path/to/Collector
tar czf collector.tar.gz --exclude='node_modules' --exclude='dist' --exclude='.DS_Store' .

scp collector.tar.gz root@RK_IP:~/

# RK2612A 上执行
ssh root@RK_IP
mkdir -p /opt/collector
cd /opt/collector
tar xzf ~/collector.tar.gz
```

### 5.5 安装依赖

```bash
cd /opt/collector/server
npm install
# serialport 原生模块会自动编译，需要 1-3 分钟

# 验证 modbus-serial 安装成功
node -e "require('modbus-serial'); console.log('modbus-serial OK')"
```

### 5.6 编译前端

```bash
cd /opt/collector/web
npm install
npm run build
# 生成的 dist/ 目录由后端静态服务
```

## 6. 配置文件调整

所有配置文件在 `/opt/collector/server/data/` 目录下。

### 6.1 串口配置 - serials.json

根据实际确认的 RS485 设备名修改：

```json
{
  "serial_max": 6,
  "serials": [
    {
      "index": 1,
      "device": "/dev/ttyS3",
      "baud_rate": 9600,
      "data_bits": 8,
      "stop_bits": 1,
      "parity": 0,
      "mode": 1,
      "lora_channel": 0
    }
  ]
}
```

**字段说明**：
- `device`：实际的 RS485 设备路径（根据第 3.3 步确认的结果填写）
- `baud_rate`：必须与 PC 端模拟器一致（默认 9600）
- `parity`：0=无校验, 1=奇校验, 2=偶校验
- `mode`：1=直连 RS485, 3=LoRa 模式

### 6.2 逆变器配置 - inverters.json

```json
{
  "inverter_max": 100,
  "inverters": [
    {
      "index": 1,
      "modbus_address": 1,
      "lora_address": 1,
      "serial_ref": 1,
      "protocol": 2,
      "model": "ginlong-3P20K"
    }
  ]
}
```

**关键字段**：
- `modbus_address`：必须与 PC 端模拟器的 `--address` 一致
- `serial_ref`：引用 serials.json 中的 index，表示这台逆变器挂在哪个串口
- `model`：决定使用哪张点表（对应 `inverter-tables/` 下的文件名）

### 6.3 采集配置 - config.json

```json
{
  "collect": {
    "modbus_timeout": 5,
    "collect_cycle": 10,
    "control_check_cycle": 2
  }
}
```

- `collect_cycle`：轮询周期（秒），联调测试时建议设为 5~10 秒，便于观察
- `modbus_timeout`：单次 Modbus 请求超时（秒）

### 6.4 前端 MQTT 地址

如果 RK2612A 的 IP 不是 `192.168.31.71`，需要修改前端的 MQTT 连接地址。

编辑 `web/src/utils/mqtt.js`，将 `BROKER_WS` 改为 RK2612A 的实际 IP：

```javascript
const BROKER_WS = 'ws://RK2612A的IP:8083/mqtt'
```

修改后需要重新编译前端：

```bash
cd /opt/collector/web
npm run build
```

## 7. 启动联调

### 7.1 启动顺序

**第一步：PC 端启动 Modbus 模拟器**

```bash
# PC 上执行
python3 modbus_simulator.py --port /dev/ttyUSB0 --address 1 --baud 9600 --model ginlong --dynamic 5
```

**第二步：RK2612A 端确认 Mosquitto 已运行**

```bash
systemctl status mosquitto
# 如果没运行：
systemctl start mosquitto
```

**第三步：RK2612A 端启动后端**

```bash
cd /opt/collector/server
MQTT_BROKER=mqtt://localhost:1883 MQTT_DEVICE_ID=001 node app.js
```

或后台运行：

```bash
nohup env MQTT_BROKER=mqtt://localhost:1883 MQTT_DEVICE_ID=001 node app.js > /var/log/collector.log 2>&1 &
```

### 7.2 观察启动日志

正常启动日志应显示：

```
[Server] 采集控制单元配置工具后端已启动 http://localhost:3000
[MQTT] 已连接 Broker: mqtt://localhost:1883
[MQTT] 已订阅: device/001/ycchange, device/001/yxchange
[Modbus] 点表已加载: ginlong-3P20K
[Modbus] 采集服务初始化中 (轮询周期: 10s, 超时: 5s)
[Modbus] MQTT 已连接: mqtt://localhost:1883
[Modbus] 已订阅遥调主题: device/001/ytcontrol
[Modbus] 串口已打开: /dev/ttyS3 (9600bps)
[Modbus] 开始轮询 (1个串口活跃)
```

如果串口打开失败，会看到警告但服务不会崩溃：

```
[Modbus] 串口 /dev/ttyS3 打开失败: Error: Error: No such file or directory...
[Modbus] 没有可用串口，轮询未启动（仅 MQTT 遥调监听生效）
```

### 7.3 验证数据流

**步骤 1：看后端日志**

每个轮询周期应看到：

```
[Modbus] 遥测变化推送: 逆变器1, 6个点
[Modbus] 遥信变化推送: 逆变器1, 2个点
[MQTT] 遥测变化更新: 1 台逆变器
[MQTT] 遥信变化更新: 1 台逆变器
```

**步骤 2：浏览器访问前端**

在 PC 浏览器打开 `http://RK2612A的IP:3000`

- 进入「实时数据」页面
- 查看「遥测(YC)」Tab：应能看到逆变器 1 的电压、电流、有功、无功等数据
- 每次轮询周期后，如果模拟器开启了动态更新，数据值会自动变化
- 右上角应显示「MQTT 已连接」

**步骤 3：用 mosquitto_sub 监听（可选）**

在 RK2612A 上另开终端：

```bash
mosquitto_sub -h localhost -t "device/001/#" -v
```

能看到 modbusService 发布的原始 MQTT 消息：

```
device/001/ycchange {"device_id":"001","timestamp":"...","inverters":[{"inverter_id":"inv_1","yc_data":[...]}]}
device/001/yxchange {"device_id":"001","timestamp":"...","inverters":[{"inverter_id":"inv_1","yx_data":[...]}]}
```

## 8. 遥调测试

### 8.1 通过前端下发

1. 进入「实时数据」页面，切到「遥调(YT)」Tab
2. 找到遥调点（如「有功调节」），输入值并点击「下发」
3. 查看 RK2612A 后端日志：

```
[MQTT] 遥调下发 -> device/001/ytcontrol: {"index":101,"value":50,...}
[Modbus] 收到遥调指令: index=101, value=50
[Modbus] 遥调写入成功: 逆变器1, 寄存器4001, 值=500
```

4. PC 端模拟器日志会显示收到了写寄存器请求

### 8.2 通过命令行下发

```bash
# 在 RK2612A 上直接发 MQTT 消息
mosquitto_pub -h localhost -t "device/001/ytcontrol" \
  -m '{"index":101,"value":50,"timestamp":"2026-03-16T12:00:00Z"}'
```

### 8.3 遥调索引说明

遥调索引采用全局编码：`逆变器编号 × 100 + 点表中的遥调索引`

| 逆变器 | 点表 YT 索引 | 全局索引 | 含义 |
|--------|-------------|---------|------|
| 1 | 1 | 101 | 有功调节 |
| 1 | 2 | 102 | 无功调节（华为） |
| 2 | 1 | 201 | 有功调节 |

在 RK2612A 上执行：

```bash
  "device_id":"001",
  "timestamp":"2026-03-16T12:00:00Z",

    "inverter_id":"inv_1",
    "yc_data":[
      {"ycnum":101,"value":220.5,"name":"A相电压","unit":"V","quality":1},
      {"ycnum":102,"value":219.8,"name":"B相电压","unit":"V","quality":1},
      {"ycnum":103,"value":221.0,"name":"C相电压","unit":"V","quality":1},
      {"ycnum":104,"value":15.3,"name":"A相电流","unit":"A","quality":1},
      {"ycnum":107,"value":502.3,"name":"有功","unit":"kW","quality":1},
      {"ycnum":108,"value":98.7,"name":"无功","unit":"kVar","quality":1}
    ]
  }]
}'
```

### 9.2 模拟遥信数据推送

```bash
mosquitto_pub -h localhost -t "device/001/yxchange" -m '{
```

### 9.3 自动循环推送脚本

```bash
# 创建测试脚本
cat > /tmp/mqtt_test_loop.sh << 'SCRIPT'
#!/bin/bash
while true; do
  V1=$((2150 + RANDOM % 100))
  V2=$((2150 + RANDOM % 100))
  V3=$((2150 + RANDOM % 100))

    \"device_id\":\"001\",
    \"timestamp\":\"$(date -Iseconds)\",
    \"inverters\":[{
      \"inverter_id\":\"inv_1\",
      \"yc_data\":[
```

## 10. 常见问题排查

### 10.1 串口权限不足

**现象**：`Error: Permission denied, cannot open /dev/ttyS3`

**解决**：

```bash
# 查看串口权限
ls -la /dev/ttyS3

# 方法1：添加用户到 dialout 组
sudo usermod -aG dialout $(whoami)
# 重新登录生效

# 方法2：修改设备权限
sudo chmod 666 /dev/ttyS3

# 方法3：以 root 用户运行后端
sudo node app.js
```

### 10.2 串口设备不存在

**现象**：`Error: No such file or directory, cannot open /dev/ttyS3`

**排查**：

```bash
# 列出所有串口设备
ls /dev/tty*

# 检查内核识别的串口
dmesg | grep -i tty

# 可能的设备名：
# /dev/ttyS0 ~ /dev/ttyS5     (标准 UART)
# /dev/ttymxc0 ~ /dev/ttymxc5 (i.MX 系列)
# /dev/ttyAMA0                (树莓派/某些 ARM)
# /dev/ttyUSB0                (USB 转串口)
```

修正 `serials.json` 中的 `device` 字段为正确路径。

### 10.3 Modbus 通信超时

**现象**：日志中反复出现 `读取失败 ... Timed out`

**排查清单**：

| 检查项 | 命令/方法 |
|--------|----------|
| 波特率是否一致 | PC 模拟器和 serials.json 的 `baud_rate` 必须相同 |
| Modbus 地址是否一致 | 模拟器 `--address` 和 inverters.json 的 `modbus_address` |
| 接线是否正确 | A 对 A、B 对 B，不要交叉 |
| 终端电阻 | 如果只有两个设备，两端都启用 120Ω 终端电阻 |
| 串口参数 | 数据位、停止位、校验位是否一致 |

### 10.4 modbus-serial 安装失败

**现象**：`npm install` 时 serialport 编译出错

**解决**：

```bash
# 确保安装了编译工具
sudo apt install -y build-essential python3 make gcc g++

# 清除缓存重新安装
cd /opt/collector/server
rm -rf node_modules package-lock.json
npm install

# 如果还是失败，单独安装 serialport
npm install serialport --build-from-source
```

### 10.5 Node.js 版本过低

**现象**：`SyntaxError: Unexpected token '?.'` 或 `modbus-serial` 报错

**解决**：确保 Node.js >= 16，推荐 18.x：

```bash
node -v
# 如果低于 16，按照 5.1 节重新安装
```

### 10.6 MQTT 前端未连接

**现象**：浏览器显示「MQTT 未连接」

**排查**：

```bash
# 确认 Mosquitto WebSocket 端口
ss -tlnp | grep 8083

# 如果 8083 没监听，检查配置
cat /etc/mosquitto/mosquitto.conf
# 确保有以下行：
# listener 8083
# protocol websockets
# allow_anonymous true

# 重启 Mosquitto
systemctl restart mosquitto
```

### 10.7 有数据但前端不更新

**排查步骤**：

1. 打开浏览器 F12 控制台，查看是否有 `[MQTT] 前端已连接` 日志
2. 查看 Network 面板的 WebSocket 连接是否有消息到达
3. 确认看的是正确的 Tab（YC 数据在「遥测」Tab，YX 数据在「遥信」Tab）
4. 点击「总召刷新」按钮，如果 HTTP 返回了数据说明后端正常，问题在前端 WebSocket

### 10.8 RK2612A 内存不足

RK2612A 只有 512MB 内存，如果同时运行太多进程可能 OOM：

```bash
# 查看内存使用
free -m

# 如果内存紧张，可以：
# 1. 关闭不必要的桌面环境
sudo systemctl set-default multi-user.target
sudo reboot

# 2. 添加 swap
sudo fallocate -l 512M /swapfile
sudo chmod 600 /swapfile
sudo mkswap /swapfile
sudo swapon /swapfile
echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab
```

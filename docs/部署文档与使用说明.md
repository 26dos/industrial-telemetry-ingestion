## 一、环境要求

### 1.1 软件环境

| 软件       | 最低版本  | 推荐版本  | 说明                     |
|-----------|----------|----------|--------------------------|
| Node.js   | 16.x     | 18.x+    | 后端运行时 + 前端构建工具    |
| npm       | 8.x      | 10.x+    | 包管理器                   |
| MQTT Broker | -      | Mosquitto 2.x 或 EMQX 5.x | 实时数据推送，非必须  |
| 浏览器     | -        | Chrome 90+ / Edge 90+ / Firefox 88+ | 前端访问 |

### 1.2 硬件环境（生产）

| 项目       | 要求                      |
|-----------|--------------------------|
| 工控机     | ARM/x86 Linux，内存 ≥ 512MB |
| 网络       | 工控机与配置终端在同一局域网    |
| 串口       | RS485 接口（按实际配置数量）   |

### 1.3 端口占用

| 端口  | 用途                        | 可配置           |
|------|----------------------------|-----------------|
| 3000 | 后端 HTTP 服务               | 环境变量 `PORT`   |
| 5173 | 前端开发服务器（仅开发环境）    | vite.config.js   |
| 1883 | MQTT Broker TCP 端口         | Broker 配置文件   |
| 8083 | MQTT Broker WebSocket 端口   | Broker 配置文件   |

## 四、生产环境部署

### 4.1 构建前端

```bash
cd Collector/web
npm run build
```

构建产物输出到 `web/dist/` 目录。

### 4.2 生产启动（单进程）

后端已内置静态文件服务，构建完成后只需启动后端即可同时提供前后端服务：

```bash
cd Collector/server
NODE_ENV=production PORT=80 node app.js
```

此时访问 `http://<工控机IP>` 即可使用（前端页面由 Express 静态托管）。

### 4.3 使用 PM2 守护进程（推荐）

```bash
# 全局安装 PM2
npm install -g pm2

# 启动服务
cd Collector/server
pm2 start app.js --name collector -- --port 80

# 设置开机自启
pm2 save
pm2 startup
```

PM2 常用命令：

```bash
pm2 list                # 查看进程列表
pm2 logs collector      # 查看日志
pm2 restart collector   # 重启服务
pm2 stop collector      # 停止服务
pm2 monit               # 监控面板
```

### 4.4 使用 systemd 管理（Linux 工控机推荐）

创建服务文件 `/etc/systemd/system/collector.service`：

```ini
[Unit]
Description=采集控制单元配置工具
After=network.target

[Service]
Type=simple
User=root
WorkingDirectory=/opt/collector/server
Environment=PORT=80
Environment=MQTT_BROKER=mqtt://localhost:1883
Environment=MQTT_DEVICE_ID=001
ExecStart=/usr/bin/node app.js
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
```

```bash
# 部署步骤
cp -r Collector /opt/collector
cd /opt/collector/server && npm install --production
cd /opt/collector/web && npm install && npm run build

# 启用服务
systemctl daemon-reload
systemctl enable collector
systemctl start collector

# 管理命令
systemctl status collector    # 查看状态
systemctl restart collector   # 重启
journalctl -u collector -f    # 查看日志
```

### 4.5 Nginx 反向代理（可选）

如需通过 Nginx 统一入口：

```nginx
server {
    listen 80;
    server_name _;

    location / {
        root /opt/collector/web/dist;
        try_files $uri $uri/ /index.html;
    }

    location /api/ {
        proxy_pass http://127.0.0.1:3000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }
}
```

## 五、MQTT Broker 部署

> MQTT 用于硬件实时数据推送。如果只使用 HTTP 接口做配置管理，可跳过此节。

### 5.1 安装 Mosquitto（推荐）

**Ubuntu/Debian：**
```bash
sudo apt update
sudo apt install mosquitto mosquitto-clients -y
```

**CentOS/RHEL：**
```bash
sudo yum install mosquitto -y
```

**macOS（开发调试）：**
```bash
brew install mosquitto
```

### 5.2 配置 WebSocket 支持

编辑 `/etc/mosquitto/mosquitto.conf`（或对应路径）：

```conf
# 标准 TCP 监听
listener 1883

# WebSocket 监听（前端浏览器连接用）
listener 8083
protocol websockets

# 允许匿名连接（开发环境）
allow_anonymous true
```

```bash
sudo systemctl restart mosquitto
```

### 5.3 验证 MQTT 连通性

打开两个终端窗口：

```bash
# 终端1：订阅
mosquitto_sub -h localhost -t "device/001/ycchange"

# 终端2：发布测试消息
mosquitto_pub -h localhost -t "device/001/ycchange" -m '{
  "device_id": "data_collector_001",
  "timestamp": "2026-03-19 10:00:00.000",
  "inverters": [{
    "inverter_id": "inv_001",
    "yc_data": [{"ycnum": 10, "value": 220.5, "name": "电压", "unit": "V", "quality": 1}]
  }]
}'
```

终端1 应收到该消息，后端日志应显示 `[MQTT] 遥测变化更新`。

## 六、环境变量与配置项说明

### 6.1 后端环境变量

| 变量              | 默认值                    | 说明                            |
|------------------|--------------------------|--------------------------------|
| `PORT`           | `3000`                   | HTTP 服务监听端口                 |
| `MQTT_BROKER`    | `mqtt://localhost:1883`   | MQTT Broker 地址（TCP 协议）      |
| `MQTT_DEVICE_ID` | `001`                    | 采集单元设备编号，决定 MQTT 话题前缀 |

设置方式：

```bash
# 方式1：命令行
PORT=8080 MQTT_BROKER=mqtt://192.168.1.10:1883 MQTT_DEVICE_ID=002 node app.js

# 方式2：写入 .env（需配合 dotenv 库，当前未集成）
```

### 6.2 前端配置

| 配置项                | 文件位置                  | 说明                  |
|----------------------|--------------------------|----------------------|
| API 代理地址          | `web/vite.config.js`     | 开发模式代理目标        |
| MQTT Broker WS 地址   | `web/src/utils/mqtt.js`  | 浏览器 WebSocket 连接  |
| 登录口令              | `web/src/views/Login.vue` | 固定口令 `admin123`   |
| 设备 ID              | `web/src/utils/mqtt.js`   | MQTT 话题中的设备编号   |

**修改登录口令：** 编辑 `web/src/views/Login.vue` 中的 `FIXED_PASSWORD` 常量，然后重新构建。

**修改 MQTT 连接地址：** 编辑 `web/src/utils/mqtt.js` 中的 `BROKER_WS` 常量：

```javascript
const BROKER_WS = 'ws://192.168.1.10:8083/mqtt'    // 改为实际 Broker 地址
const DEVICE_ID = '002'                              // 改为实际设备编号
```

## 七、数据文件说明

后端所有配置数据以 JSON 文件存储在 `server/data/` 目录，支持热编辑。

### 7.1 文件清单

| 文件                   | 说明                          | 对应接口               |
|-----------------------|------------------------------|----------------------|
| `config.json`         | 系统全局配置                    | getConfigInfo / setConfigInfo |
| `network.json`        | 工控机网络配置                  | getNetwork / setNetwork |
| `lora.json`           | Lora 无线模块配置               | getLoraInfo / setLoraInfo |
| `serials.json`        | 串口列表及参数 + 最大数量约束     | getSerialInfo / setSerialInfo / getSerialMax |
| `inverters.json`      | 逆变器列表及参数 + 最大数量约束   | getInverterInfo / setInverterInfo / getInverterMax |
| `104-use.json`        | 当前启用的 104 转发表名称        | get104List / set104File |
| `inverter-tables/*.json` | 逆变器点表文件（按型号命名）   | getInverterTableList / Info / upload / delete |
| `104-tables/*.json`   | 104 转发表文件                  | get104List / Info / upload / delete |

### 7.2 备份建议

```bash
# 定时备份配置目录
cp -r /opt/collector/server/data /opt/collector/backup/data_$(date +%Y%m%d)
```

### 8.5 串口管理

**路径：** 侧边栏 → 串口管理

**功能：** 管理工控机的 RS485/RS232/Lora 串口通道

| 字段       | 说明                                | 可选值                                |
|-----------|-------------------------------------|--------------------------------------|
| 设备路径   | Linux 设备文件路径                    | `/dev/rs485-1` 等                    |

## 九、接口调试指南

所有接口统一使用 **POST** 方法，参数放在 **JSON body** 中。

## 十、常见问题与排查

### Q1: 启动后端报 `EADDRINUSE: address already in use :::3000`

端口被占用，两种解决方式：

```bash
# 方式1：换端口
PORT=8080 node app.js

# 方式2：找到并结束占用进程
lsof -i :3000
kill -9 <PID>
```

### Q2: 后端日志提示 `[MQTT] 连接错误: connect ECONNREFUSED`

MQTT Broker 未启动或地址配置不正确。

- 如果不需要实时推送功能，可以忽略此错误，HTTP 接口正常使用
- 如果需要 MQTT，请参照 [第五节](#五mqtt-broker-部署) 部署 Broker

### Q3: 前端开发模式下 API 返回 404 或跨域错误

检查后端是否已启动在 3000 端口。前端 Vite 配置了代理：

```javascript
// web/vite.config.js
proxy: {
  '/api': {
    target: 'http://localhost:3000',
    changeOrigin: true,
  },
}
```

### Q4: 生产环境前端页面空白

确认是否已构建前端：

```bash
cd web && npm run build
```

并确保 `web/dist/` 目录存在。后端会自动托管此目录。

### Q5: 上传点表文件后列表没有更新

- 确认上传的文件为合法的 `.json` 格式
- 文件名即为点表名称（去掉 `.json` 后缀）
- 检查 `server/data/inverter-tables/` 或 `server/data/104-tables/` 目录是否有新文件

### Q6: MQTT 前端显示"未连接"

前端 MQTT 通过 WebSocket 连接 Broker，需确保：

1. Broker 已开启 WebSocket 监听（默认 8083 端口）
2. `web/src/utils/mqtt.js` 中 `BROKER_WS` 地址正确
3. 浏览器能访问该地址（防火墙/安全组放通 8083）

### Q7: 修改登录口令

编辑 `web/src/views/Login.vue`：

```javascript
const FIXED_PASSWORD = 'your_new_password'    // 修改此处
```

修改后需重新构建前端：`cd web && npm run build`

| unit        | 单位                       |

## 附录 B：逆变器点表文件格式

文件名即型号名，如 `huawei-SUN2000-100KTL-M2.json`，包含四个数组：

```json
{
  "yc": [
    {
      "index": 1,
      "name": "A相电压",
      "register": 32069,
      "data_type": "U16",
      "byte_order": "ABCD",
      "factor": "0.1",
      "dead_zone": "0.1"
    }
  ],
  "yx": [
    {
      "index": 5,
      "name": "发电",
      "register": 32089,
      "data_type": "U16",
      "byte_order": "ABCD",
      "bit_offset": 0,
      "bit_count": 8,
      "valid": 2
    }
  ],
  "yt": [
    {
      "index": 1,
      "name": "有功调节",
      "register": 40120,
      "data_type": "U16",
      "byte_order": "ABCD",
      "factor": "0.1",
      "value": 0,
      "use_defalut": 0,
      "link_index": 0,
      "restore_index": 5
    }
  ],
  "collect": [
    {
      "index": 1,
      "start_addr": 32069,
      "end_addr": 32077,
      "funcode": 3
    }
  ]
}
```

| 数组      | 说明              | 关键字段                              |
|----------|-------------------|---------------------------------------|
| yc       | 遥测点定义         | register(寄存器), data_type, factor    |
| yx       | 遥信点定义         | register, bit_offset, bit_count, valid |
| yt       | 遥调点定义         | register, factor, value, use_defalut   |
| collect  | Modbus 采集段定义   | start_addr, end_addr, funcode         |

`data_type` 可选：`U16` / `I16` / `U32` / `I32`  
`byte_order` 可选：`ABCD` / `DCBA` / `BADC` / `CDAB`

| 字段      | 说明                                |
|----------|-------------------------------------|
